# 图片头像上传与可移植安装器设计

日期：2026-08-15
状态：已与用户逐节确认，等待最终规格审查

## 1. 背景

现有系统由 llama.cpp、Hugging Face speech-to-speech、Qwen TTS、faster-whisper 和 LiveTalking/Wav2Lip 组成，已经能在本机完成中文语音对话、语音回复和数字人口型驱动。当前数字人头像需要在命令行外部生成，并由启动配置指定；安装路径、模型和运行时也与当前电脑绑定。

本设计解决两个问题：

1. 在 `http://127.0.0.1:7860` 的设置窗口中提交静态图片，预览裁剪，生成 Wav2Lip 头像并自动切换。
2. 将整套系统改造成可部署到其他 Windows + NVIDIA 电脑的小型联网安装包，根据目标显存推荐和下载合适的 LLM。

## 2. 目标与非目标

### 2.1 目标

- 图片上传入口位于现有对话页的设置窗口内。
- 上传后先进行本地裁剪预览，用户确认后才提交生成。
- 头像生成期间不影响当前数字人和对话。
- 生成完成后在安全时机自动切换，不重启 llama.cpp、s2s 或 LiveTalking 服务。
- 切换失败时自动恢复旧头像。
- 支持浏览、切换和删除已生成头像。
- 程序、模型、用户数据和机器配置相互分离，不依赖固定盘符。
- 提供小型联网安装器、断点续传、哈希校验、硬件探测和一键维护。
- 第一版支持 Windows 10/11 与 NVIDIA RTX 20/30/40/50 系列。
- RTX 50/Blackwell 使用支持 `sm_120` 的 PyTorch CUDA 12.8 组件。

### 2.2 非目标

- 第一版不原生支持 AMD、Intel GPU、macOS 或 Linux。
- 第一版不把服务暴露到公网或局域网。
- 第一版不提供云端账户、头像同步或模型托管。
- 第一版不在浏览器中训练或微调口型模型。
- 第一版不自动生成人物图片，只处理用户主动选择的本地图片。

## 3. 已评估方案

### 3.1 浏览器生成短视频，再调用旧视频接口

优点是后端改动较少；缺点是浏览器视频编码兼容性差、内存占用不稳定，而且错误定位困难。因此不采用。

### 3.2 LiveTalking 新增图片任务接口（采用）

浏览器只负责交互式裁剪和导出标准图片。LiveTalking 校验图片、创建短视频输入并复用现有 Wav2Lip 任务系统。该方案保留成熟的人脸检测与头像生成链路，并且 LiveTalking 已具备任务状态、CORS 和动态头像加载能力。

### 3.3 由 s2s Demo 后端代理全部头像逻辑

优点是浏览器只访问同源接口；缺点是让语音项目承担数字人数据和生成逻辑，增加耦合。因此不作为主架构。前端从现有 iframe URL 推导 LiveTalking 的 origin，并直接访问其本地 API。

### 3.4 部署方式比较

- 大型便携压缩包：离线方便，但体积大、更新慢、难以按硬件选择模型。
- Docker：环境一致，但 Windows GPU、麦克风和 WebRTC 配置复杂。
- 小型联网引导安装器（采用）：只携带安装逻辑和清单，按机器下载经过校验的组件和模型。

## 4. 总体架构

```text
7860 对话页设置窗口
  ├─ 本地图片选择与 3:4 裁剪预览
  ├─ 调用 8010 图片头像任务 API
  ├─ 轮询生成进度
  └─ 控制数字人 iframe 安全重连
                │
                ▼
8010 LiveTalking
  ├─ 图片验证与人脸预检
  ├─ 临时短视频构造
  ├─ 复用 Wav2Lip AvatarTask
  ├─ 头像目录与元数据管理
  └─ 通过 /offer 按 avatar ID 动态加载
                │
                ▼
8765 s2s
  └─ 将 TTS PCM 转发到唯一的活动 LiveTalking 会话
```

运行时继续只监听 loopback。头像切换通过重建 iframe 内的 WebRTC 会话完成，LLM 和语音会话不因头像变化而重启。

## 5. 设置窗口交互

### 5.1 头像区域

设置窗口新增“数字人头像”区域，包含：

- 当前头像缩略图和显示名称。
- “选择图片”按钮。
- “已有头像”列表和“切换”操作。
- 非当前、非内置头像的“删除”操作。
- 当前任务的阶段、进度和可读错误信息。

### 5.2 裁剪流程

1. 接受 JPEG、PNG、WebP，前端先检查大小不超过 10 MiB。
2. 使用浏览器本地 URL/Canvas 显示图片，原图此时不上传。
3. 裁剪框固定为 `3:4`，支持拖动、缩放、居中和重置。
4. 实时预览最终 `576 × 768` 画面。
5. 用户可以填写显示名称；存储 ID 由服务端生成，名称不参与路径拼接。
6. 点击“生成并切换”后，Canvas 输出标准 JPEG Blob 并提交。

### 5.3 任务反馈

前端展示以下阶段：

- 上传中
- 验证图片
- 检测人脸
- 生成头像
- 准备切换
- 连接新头像
- 完成或失败

生成期间旧头像和现有对话继续工作。用户关闭设置窗口后任务仍继续，重新打开时可恢复任务状态。

### 5.4 安全切换

1. 生成任务完成后，等待当前 TTS 回复结束且主状态回到可监听状态。
2. 临时暂停麦克风输入，避免切换窗口内触发新回复。
3. 父页面向旧 iframe 发送显式关闭消息；iframe 关闭 PeerConnection 并取消自动重试。
4. 父页面根据旧 `sessionid` 轮询管理接口，确认旧会话已经释放。
5. iframe 使用 `embed.html?avatar=<avatar_id>&v=<cache_key>` 重载。
6. embed 读取并校验 avatar 查询参数，将其放入 `/offer` 请求体。
7. 新 WebRTC 连接成功且返回新 `sessionid` 后，服务端才将新头像记为 active。
8. 父页面恢复麦克风和正常状态。

若新连接超时或失败，页面按相同步骤恢复旧头像。切换期间任何错误都不能留下两个活动数字人会话，以免 s2s 把 PCM 转发给错误头像。

## 6. LiveTalking API

所有响应沿用 `{ "code": 0, "msg": "ok", "data": ... }` 包装格式。

### 6.1 创建图片头像任务

`POST /api/avatar/image-task`，`multipart/form-data`：

- `image_file`：必填，浏览器裁剪后的图片。
- `display_name`：可选，仅作为显示文本。
- `task_id`：可选，主要供测试或恢复使用。

成功响应包含 `task_id`、`avatar_id`。服务端生成的 `avatar_id` 使用安全前缀、时间和随机后缀，不接受客户端文件路径。

### 6.2 查询任务

继续使用 `GET /api/avatar/task/{task_id}`。任务数据增加稳定的 `stage` 字段以及结果中的 `avatar_id`。原有视频任务保持兼容。

### 6.3 头像目录

- `GET /api/avatar/list`
- `GET /api/avatar/active`
- `GET /api/avatar/{avatar_id}/thumbnail`
- `POST /api/avatar/activate`，JSON `{ "avatar_id": "...", "sessionid": "..." }`
- `DELETE /api/avatar/{avatar_id}`

active 返回持久化的当前头像；embed 未收到显式 avatar 查询参数时，先读取该接口再创建 `/offer`，因此刷新浏览器和重启服务后仍使用已选择的头像。activate 只接受当前确实存在且对应头像 ID 的活动会话。内置头像、当前头像、存在活动会话的头像不能删除。

### 6.4 本机管理接口认证

安装器首次运行时生成高熵随机管理令牌，分别写入 demo 和 LiveTalking 的机器配置。设置页从同源 `/api/config` 获得短期页面能力值，请求 8010 的头像创建、激活和删除接口时通过自定义请求头携带。LiveTalking 同时校验：

- 管理令牌有效；
- `Origin` 为安装器配置的本机 7860 页面；
- Host 与监听地址仍为 loopback。

图片生成、激活、删除和任务详情不允许匿名跨站调用。公开缩略图和运行健康检查不返回本地路径或敏感配置。令牌使用自定义请求头，使浏览器跨站简单表单无法触发写操作；失败响应不泄露期望令牌。

### 6.5 图片验证

- 请求体硬限制 10 MiB。
- 根据文件签名和实际解码结果判断格式，不信任扩展名或浏览器 MIME。
- 解码后限制像素总量，防止解压炸弹。
- 最终输入必须为 `576 × 768`，方向信息在解码时归一化。
- 预检必须找到一个主要人脸；无脸、多张显著人脸、脸部过小或关键区域越界时返回明确错误。
- 临时文件使用服务端生成的名称并限制在专用 temp 目录。

## 7. 头像生成和存储

标准数据根目录：

```text
LiveAvatarData/
├─ config/
│  ├─ app.json
│  └─ active-avatar.json
├─ hardware/
│  └─ profile.json
├─ models/
├─ avatars/
│  └─ <avatar_id>/
│     ├─ full_imgs/
│     ├─ face_imgs/
│     ├─ coords.pkl
│     ├─ thumbnail.jpg
│     └─ metadata.json
├─ cache/
├─ logs/
└─ temp/
```

服务端将确认后的静态图构造成短时、固定帧率的无声视频，再调用现有 Wav2Lip `generate_avatar`。这样保留已有检测、坐标和平滑逻辑，同时避免在任务系统中维护第二套头像生成算法。

输出先写入同一磁盘上的 staging 目录。所有必要文件验证成功后再原子改名为正式头像目录。失败或取消时清理上传图片、临时视频和 staging 数据。正式目录只保留裁剪图的派生帧、缩略图和元数据，默认不保留原始上传文件。

`metadata.json` 至少记录：schema 版本、avatar ID、显示名称、创建时间、生成模型、画面尺寸、源图哈希、应用版本和内置标记。

## 8. 可移植安装布局

默认采用当前用户范围安装，无需管理员权限。默认程序目录为 `%LOCALAPPDATA%\LiveAvatar`，安装器允许选择其他可写磁盘。

```text
<install-root>/
├─ app/
│  └─ versions/<app-version>/
├─ runtime/
├─ launcher/
└─ data/                 # LiveAvatarData，可单独选择其他磁盘
```

启动脚本不写死盘符，而是从自身位置解析 install root，再读取 `data/config/app.json`。批处理只作为兼容入口，实际启动器负责环境变量、端口、PID、日志和健康检查。

程序升级写入新的 version 目录，验证通过后原子切换 current 版本；失败则保留旧版本。模型、头像、缓存和用户配置不进入版本目录。

## 9. 联网安装器

### 9.1 清单

`components.json` 描述：

- Python 3.11 运行时
- llama.cpp Windows CUDA 包
- speech-to-speech 固定提交及补丁版本
- LiveTalking 固定提交及补丁版本
- PyTorch、torchvision、torchaudio 组合
- faster-whisper、Qwen TTS 和其他运行资源
- 下载 URL、备用镜像、字节大小、SHA-256、兼容条件

`models.json` 描述每个 LLM 候选：

- 模型 ID、别名和量化格式
- GGUF 文件名、大小、SHA-256 和下载源
- 实测的最低整机显存、推荐显存和运行时预留
- 默认上下文、GPU layers 和内存安全参数
- 质量档位和人工可读说明

安装器发布时固定清单版本。下载使用 HTTPS，文件只有在字节大小和 SHA-256 均匹配后才进入正式目录。

### 9.2 硬件探测与模型选择

安装器检测：

- Windows 版本和架构
- GPU 名称、显存、驱动版本和可用 CUDA 能力
- 系统内存
- 安装盘与模型盘可用空间
- 已占用端口

模型选择不简单地把总显存全部交给 LLM。每个候选的 `minimum_total_vram_mib` 必须包含 TTS、Whisper、Wav2Lip 和安全余量的端到端实测预算。安装器选择不超过检测显存的最高默认质量档位，并提供：

- 推荐：稳定平衡
- 更快：更小模型或更低量化
- 更高质量：仅在满足安全预算时可选

初始策略档位为：32 GiB 以上推荐 35B Q4；20–31 GiB 推荐中型模型；12–19 GiB 推荐 9B/14B 量化；8–11 GiB 推荐 4B/9B 较低量化；更低显存只提供部分卸载或 CPU 慢速模式。最终具体模型、阈值和上下文由经过整套链路测试的 `models.json` 决定，而不是散落在安装代码中。

RTX 50/Blackwell 选择支持 `sm_120` 的 PyTorch CUDA 12.8 栈。其他 NVIDIA 架构由组件清单匹配经过验证的兼容栈；驱动不满足最低要求时先阻止大文件下载并给出升级提示。

### 9.3 下载与恢复

- 支持 HTTP Range 断点续传。
- `.partial` 文件不作为已安装组件。
- 官方源与配置的镜像可切换；切换源不跳过哈希校验。
- 安装前展示下载量、安装空间和目标目录。
- 网络中断后可从维护工具继续。
- 失败只回滚本次组件，不删除已验证模型或用户数据。

### 9.4 安装完成验证

安装器依次验证：

1. Python 版本和两个虚拟环境依赖完整性。
2. PyTorch 版本、CUDA 版本、GPU capability 和一次 tensor smoke test。
3. llama.cpp 能加载选定模型并通过 `/health`。
4. faster-whisper 与 Qwen TTS 模型文件完整。
5. LiveTalking 能加载默认头像和 Wav2Lip 模型。
6. 8080、8010、8765、7860 四个服务健康。
7. 浏览器配置返回正确 WebSocket 和数字人 URL。

通过后创建“Live Avatar”“停止 Live Avatar”和“Live Avatar 维护工具”用户级快捷方式。

## 10. 配置、迁移和卸载

`app.json` 使用相对路径或以 install/data root 为基准的可重定位路径。机器探测结果与用户选择分开保存，避免把旧电脑的 GPU 配置直接迁到新电脑。

管理令牌属于本机配置，不进入迁移包。迁移到另一台电脑时由安装器重新生成。

迁移包默认包含：

- 自定义头像及元数据
- 当前头像选择
- 非敏感应用设置
- 可选的模型目录索引

迁移包默认不包含日志、临时文件、硬件 profile、缓存或访问密钥。导入到新电脑后重新执行硬件探测和模型兼容性检查。

卸载器分别询问是否保留：

- 已下载模型
- 自定义头像
- 应用设置

任何默认选项都不得静默删除用户头像。

## 11. 错误处理与可观察性

- UI 错误信息区分格式错误、无脸、多脸、脸太小、生成失败、会话释放超时、新头像连接失败和磁盘不足。
- 所有任务日志带 `task_id`，切换日志带旧/新 `sessionid` 和 avatar ID，但不记录图片内容。
- 维护工具显示组件版本、端口、PID、GPU 占用、模型路径和最近失败摘要。
- 健康检查失败时提供“重试”“修复缺失组件”“打开日志目录”，不直接清空环境重装。

## 12. 测试策略

### 12.1 前端

- 支持格式、大小限制和 EXIF 方向。
- 横图、竖图、极大图片的裁剪范围与 `576 × 768` 输出。
- 取消、重试、关闭设置后恢复任务。
- 生成中旧头像继续工作。
- 切换时麦克风暂停和恢复。
- 新连接失败后恢复旧头像。

### 12.2 API 与数据

- 正常单人图片生成完整头像目录。
- 无脸、多脸、损坏文件、伪造 MIME、超限文件和路径注入被拒绝。
- 相同显示名称不覆盖已有头像。
- staging 原子提交以及失败清理。
- active、内置和正在使用的头像不能删除。
- 缺少/错误管理令牌、错误 Origin 和非 loopback Host 的管理请求被拒绝。
- 旧视频任务 API 保持兼容。

### 12.3 运行链路

- 新头像 `/offer` 返回与请求一致的 avatar ID。
- 旧会话释放后只保留一个活动 session。
- TTS PCM 被送到新 session，人物口型和声音同步。
- 切换过程中 llama.cpp 和 s2s 会话不重启。

### 12.4 安装与升级

- 至少覆盖 RTX 20、30、40、50 系列代表机器或等价 CI/测试机。
- 验证低空间、断网续传、镜像切换、坏哈希、驱动过旧、端口占用和安装目录含空格/中文。
- 验证程序升级保留模型、头像和配置。
- 验证导出包在另一台机器导入后重新探测硬件，不复用旧 GPU profile。

## 13. 验收标准

- 用户可在设置窗口完成选择、裁剪、生成和自动切换，无需命令行。
- 失败不会破坏当前头像、当前对话或已有头像数据。
- 切换完成后只有一个活动 LiveTalking 会话，回复声音和口型进入新头像。
- 关闭并重新打开页面或服务后仍使用已激活头像。
- 小型安装器可在受支持的新电脑上选择路径、探测显存、推荐模型、断点下载并完成端到端自检。
- 所有下载组件可通过固定大小与 SHA-256 追溯验证。
- 所有程序路径均可重定位，不依赖开发机的 `C:\`、`E:\` 或用户名。

## 14. 实施顺序

1. 先实现并测试 LiveTalking 图片任务、头像目录和 active 状态 API。
2. 扩展 embed 的 avatar 参数、关闭握手和会话报告。
3. 在 s2s 设置窗口实现裁剪、任务进度、列表和安全切换。
4. 完成端到端声音与口型回归测试。
5. 抽离路径和机器配置，建立版本化组件与模型清单。
6. 实现联网安装器、维护工具、迁移与卸载流程。
7. 在代表性 NVIDIA 显卡档位上测量整套显存并冻结首版模型目录。
